# 2026-10-22 当前测试与选优规则

**本日后续用户明确更新：不再要求同一场景最多三次。下文三次硬上限为历史规则，已被本段取代。保留累计台账、全部失败和分组统计；重复同场仅作重复性证据，竞争力需多布局/多席位配对验证。不无限重试或挑最好结果。**

用户最新说明是“每个不同测试最多3次”“代码迭代重置次数，取平均来证实迭代的效果”，并要求比赛规则优先。当前以此为准。v0.9.1及更早笔记中的“整个阶段累计三场、改代码也不能重测”已废止；历史尝试与失败仍保留。

- 每次真实代码迭代、每个固定场景最多执行3次，达到3次自动停止；失败和准备失败也计次数。
- `verification_budget.py` 对生产C++源文件、头文件和构建定义计算指纹。改版本标签、文档、解压路径不会重置。恢复原代码后仍使用原指纹的台账。
- 新源码下的计数位于 `experiments/iterations/<指纹>/match-ledger.json`；发布包还保存已用计数基线。旧根目录台账为历史记录，不再作为全阶段限额。
- 比较时固定地图内容与哈希、席位、对手实现、Tick周期、总Tick、CPU分配、模型及输出上限。不同地图、不同对手、静止对手和四车对抗分别统计。
- 每组报告全部尝试数、完成数、通过数，得分均值、样本标准差、最小和最大值；未完成场不伪造0分，明确有效得分样本数。不得只选最好一场。
- 三次重复只是早期筛选；固定图上的确定性复现不能证明未知图胜率。优先看合规、无效动作、回执和真实调用资格，其次才比较得分和时延。
- 构建诊断按实际配置分别计数：Release、ASan/UBSan、O3/LTO具有不同的检测行为，是不同固定测试配置；同一配置修复夹具后仍累加原次数，不重置生产源码指纹。不得用无实质差异的配置改名规避上限。
- Prompt离线真实调用按固定输入和具体实现分别计数。换数字后的开发验证样本经过迭代使用后，不再称为独立盲测。
- 真实付费测试费用由用户DeepSeek账户承担；不设虚构的累计付费调用上限。所有调用仍经过未修改的练习代理，遵守令牌额度、频率和并发要求。

复核工具：`python3 -B tools/summarize_competitive_results.py <同组result.json...> --output summary.json`。工具按源码、二进制、地图、模式、对手和CPU条件分组，保留失败，拒绝重复计入同一场或一组超过三次。测试工具不被参赛节点导入，也不向规划器提供裁判全图。

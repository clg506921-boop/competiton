# 真实模型对照与竞赛迭代

2026-10-22。目标是提升比赛竞争力，先解决会损失事件响应机会的实际问题，再用同条件平均值筛选版本。比赛规则与v1.1.1为底层约束，v1.1.2作补充；官方裁判、二进制和内置配置均未改。

## 1. Prompt不是越短越好

增加独立的 `event_eval_tool`：生成与节点相同的Prompt，并调用同一份C++输出规范化、Schema和语义校验代码评估返回值。评测工具不初始化ROS、不接收密钥、不联网。

通过原练习代理接入用户DeepSeek账户，裁判一直暂停在Tick0。训练对照包含爆炸和易伤，每例每种Prompt各3次；轮换调用顺序。扩展验证覆盖其余6类事件及4个不同参数/措辞样本，各3次。后两轮共用的开发样本不是独立盲测。

最终同组6次对照：旧版平均7200.31ms，样本标准差2809.72ms；示例版平均2118.91ms，标准差578.44ms。采用版连同扩展验证共36/36正确，平均2196.96ms，标准差535.71ms，最大3204.78ms。12种输入下，生产入口与选中示例版生成的messages逐项一致。

三轮共120次实际请求，代理均成功。模型为练习自备deepseek-flash，max_tokens=2048；这些不是正式公告参数。测试用40秒HTTP等待观察完整输出，并单列是否满足生产10秒阈值；因此这组数据不证明生产libcurl超时、公告到动作或正式得分。初轮和第二轮的失败全部保留。

## 2. 保留严格语义检查

改动集中于提示词：area给出真实JSON对象；易伤统一结束Tick放在事件根部；推导时间交给校验器；天使点存在期、入点窗口与个人回血时长分别说明。示例使用不同坐标和数值，只是模型输入；本地不按公告关键词、数字、句式或固定日程解析事件。

Schema、规范样例、事件参数检查和本地个人效果计算条件不放宽。错误输出仍拒收，动作线程继续本地决策。v0.10三次构建后的14组原生回归均通过，ROS构建通过；最后一次生产Prompt源码与编译证据一致。

## 3. 24×24实际对抗发现的新问题

新增自有外部测试图，官方校验器通过：24×24、16资源、总价值200，任务点[12,12]，A/B/C/D出生点与静态连通性已检查。只通过官方 `--config` 加载，不改官方stage2.json。全图只供测试器布置场景，节点仍只用本队合法感知。

v0.10三场均完整500Tick、得分42.5，资源50、有效伤害340、任务3、无效动作0；得分均值42.5，样本标准差0。固定输入下结果一致，并非未知地图胜率结论。

实战日志显示，生效/结束公告可能耗尽思考Token或超时；FIFO待发队列会让更晚的新预告排在陈旧消息后。一场中Tick40看到的公告直到Tick202才消费，说明单看静态预告解析成功不够。v0.10这组保留为下一轮实战基线。

## 4. 下一轮有针对性的实现

v0.11保留一个待发任务，允许观测时间更晚的公告替换尚未发送的旧公告；不打断在途请求。旧请求的重试不得挤掉较新的待发任务。丢弃未发送任务及跳过重试单独计数；只依据公开消息到达Tick排序，不判断事件语义。

已知DeepSeek模型使用冻结在代码中的非思考请求规则，其他模型使用通用字段；若网关400拒绝可选字段，同一调度器记住兼容性结果，至多补一次通用请求，仍受每来源最多两次发送限制。max_tokens、stream=false、统一网关、单worker和超时安全门均保留。该规则须随代码与Prompt赛前封存，不是现场可随意切换的decision_type参数。

DeepSeek当前接口明确提供thinking开关且默认开启，见[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。正式模型和网关能力按公告确认，当前实测只说明练习接入条件。

## 5. 次数与平均值

按用户最新澄清：真实代码迭代后重置该版本固定场景的最多3次计数，保留原版本历史。源码指纹识别代码，改文档、版本标签、路径不会产生新额度。比较固定地图哈希、对手、席位、Tick与硬件安排，记录全部结果与波动；不同配置不混平均。当前实现和复核入口见包内docs/verification-policy.md。

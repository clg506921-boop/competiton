# 统一调整窗口与暂停切换预案

2026-10-22，肥鱼说的都队。依据所给规则§2.3；本页为准备材料，尚未获裁判登记或批准。实际执行由队伍按当场书面通知办理。

## 三种操作场景

| 场景 | 可准备的内容 | 生效条件 |
| --- | --- | --- |
| 阶段封存前 | 自研代码、研究方案、Prompt、参数、两种decision_type | 验证后固定版本与登记；不能混用不同构建证据 |
| 第一阶段结束后的统一调整窗口 | 参数、Prompt、任务解析逻辑 | 规则明确允许的范围；开始/结束以统一安排为准，结束后确认第二阶段版本 |
| 封存后暂停/加赛前策略切换 | decision_config.json唯一键decision_type，值限已登记balanced/collect | 裁判批准并登记，每队每场最多两次；涉及重启同时遵守重启规则 |

后续淘汰轮次不自动产生调整窗口。规则没有把统一窗口等同于任意重写算法许可。超出明确范围的改动先向裁判确认；不以修改接入地址/令牌为名改变决策逻辑。

## 预备候选与现有证据

| 候选 | 可以解决的问题 | 本地证据/限制 |
| --- | --- | --- |
| balanced / collect | 对抗收益与保守攻击准入 | 已实现和离线验证，需赛前登记；不是实时人工战术入口 |
| 现有greedy / lookahead / frontier | 第一阶段采集路线差异 | 仅研究实现，未形成当前版本公平批量优胜结论，须在封存前固定 |
| immediate / mailbox | 回调直接发布与最新帧邮箱 | 研究实现，正式默认immediate；不得把更换名称当成新测试额度 |
| O2 / O3-LTO / ASan-UBSan | 速度、可诊断性、构建差异 | 有构建预置，当前本轮验证Release；不声称所有预置均已等价验收 |
| 当前模型输出契约Prompt | 减少缺必需字段、截断或整体结构不符 | v0.7离线诊断已通过；真实拒收根因仍未追溯，没有新的真实成功证明 |
| 公告模型/L/网关/配额 | 正式AI接入 | 必须以公告或明确认可为准，不现场猜测L、改10/25秒常量或添加供应商选项 |

正式decision_type仅两个，不把研究选项或构建配置加入临时登记。场上不能改目标坐标、动作、权重或临时指令。

## 统一窗口执行顺序

1. 保存第一阶段结束场次、成绩、原代码/配置/Prompt哈希和日志，不覆盖已封存包。
2. 记录窗口公告的起止时间、允许范围及拟改动。缺少明确许可的内容先保留原版。
3. 先完成本场接入字段核对，再处理被允许的参数/Prompt/任务解析变更；每项注明原因与影响。
4. 查test-execution-ledger.json，只执行有剩余额度且与变更相关的用例。已三次的场景暂停，不以版本/配置重命名重置；构建不是用例复验。
5. 对源码、无密钥配置和Prompt逐项差异审查，检查令牌未入包。记录构建选项和二进制哈希。
6. 在窗口结束前向裁判确认第二阶段版本及两模式；待机前完成本场网络、感知、动作、执行回执与真实AI检查并保存证据。

## 暂停时切换既有模式

程序只在启动读取配置，不支持热加载。获准切换若需要重启，必须同时登记重启，不预设该次豁免、不反复自动拉起。程序不会依据文件修改在运行中悄悄改变策略。

```text
场次/session、席位：
封存版本与哈希：
当前模式 → 申请模式：
本场已用切换次数 / 2：
是否涉及重启、该阶段已用重启次数：
申请原因（不夹带逐Tick动作）：
裁判批准/登记时间及依据：
暂停时修改的文件唯一差异：decision_type
恢复后首个有效感知/动作/回执Tick：
执行人、复核人：待队内分工确定
```

赛前接入调整另记录席位、队名、域、网络、网关与令牌来源，不记录令牌内容。同ID裁判重置后的重新接入、正常重启是否计额度仍待官方确认。

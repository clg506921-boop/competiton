# 构建配置检查与测试夹具生命周期修复

2026-10-22。本轮在9场比赛全部停止之后，使用独立目录检查ASan/UBSan与O3/LTO，不让并行编译干扰比赛对照。默认运行版本仍为Release O2，没有用Sanitizer或O3结果冒充更高分。

## 发现的实际问题

ASan首轮在events_tests.cpp第17行报告heap-use-after-free。根因是测试循环直接遍历examples()["cases"]；examples()返回临时JSON，取子项引用后所有者已经结束生命周期，循环再访问失效内存。第二个normalization_cases循环有相同写法。

修复方式是先保存JSON所有者，再遍历子数组：

```cpp
const auto fixture = examples();
for (const auto& item : fixture["cases"]) {
    // 原有断言保持不变
}
```

只改test/events_tests.cpp两处所有者生命周期，没放宽断言、没修改样例JSON、Schema或生产解析器。检索同形写法仅发现这两处测试循环。最初把故障笼统称为“事件校验路径”不够精确，最终栈定位属于测试夹具；不能声称修复了生产解析器的同类故障。

# 赛前接入：填一份文件，检查后启动

**最新提前通知将计分改为500 HP阈值、死亡扣60及击杀分享60；v1.1正文待发布。本代码候选仍是v1.0，模板新增rules_version核对，填写v1.1会明确拒绝启动，避免误用旧伤害策略。此字段只检查兼容性，不允许现场切换计分算法。**

依据已提供赛事规则2.1、2.3和通信协议1、5：ROS域、裁判地址、席位、网关、模型、输出限制、配额及当场令牌由官方赛前/赛次通知提供。它们不是现在就必须让用户补齐的信息，也不是可自行推断的固定比赛值。

## 公告到达后做什么

1. 将`match-settings.example.json`复制到源码包外的私有位置，例如`/home/ubuntu/rmtc-private/match-settings.json`。只填公告值，本场令牌也放这份私有文件；文件不加入源码、报告或提交ZIP。
2. 第一阶段填`stage="1"`、`seat="A"`及网络信息，AI字段可以保持null。第二阶段填`stage="2"`（或已封存的auto），再填网关、令牌、max_tokens和配额。
3. 在程序目录运行：

```bash
bash prepare_match.sh --check /home/ubuntu/rmtc-private/match-settings.json
```

检查通过并到达裁判指定的启动时机后：

```bash
bash prepare_match.sh --launch /home/ubuntu/rmtc-private/match-settings.json
```

不需要改C++、Prompt或重新编译；不需要手动拼export、令牌命令行、端口或话题。脚本先复用生产配置校验及本地预检，再将参数通过进程环境传给既有启动器，保留席位实例锁。启动仍须遵守封存、暂停和批准重启流程。

## 每项填什么

| 字段 | 内容 |
| --- | --- |
| rules_version | 官方规则版本；当前实现仅接受`"v1.0"`，升级v1.1后随封存版本更新；null表示尚未核对 |
| seat | 本场A/B/C/D；正式第一阶段只用A |
| stage | `"1"`、`"2"`或`"auto"`；这不是decision_type |
| team_name | 已填写“肥鱼说的都队”，不用每场重填 |
| referee_host | 官方裁判机IP/主机名；不带http前缀 |
| ros_domain_id | 官方ROS域整数，不沿用练习27 |
| network | 正式使用`"wired"`，自动设置ROS_LOCALHOST_ONLY=0；练习本机可选`"local"` |
| gateway_url | 官方公布的网关基地址或完整`/v1/chat/completions`地址，脚本自动补端点，不猜8000/8080 |
| team_token | 本场本席位的裁判令牌；不是DeepSeek上游密钥 |
| model | 有公布名称就原样填写；null/空字符串按通信协议采用官方默认模型，不猜练习模型名 |
| max_tokens | 官方输出上限L正整数；未知就保留null，检查会明确列出缺项，不套用练习2048 |
| ai_quota | 官方每场调用配额正整数；不套用练习100；未知/0不解释成无限额度 |

缺项会按字段名集中报告。输出不会回显令牌、整份JSON或服务器错误正文。检查不发HTTP请求、不启动ROS，不据此声称DDS、真实AI资格已验收。

## 换场与封存

新场次只更新公告允许的接入信息，再检查、按规定重启。环境中的旧AI配置、旧令牌会被替换，不需要人工逐个清理。`decision_config.json`继续独立按登记和批准流程使用，接入文件拒绝坐标、动作、目标或新增策略字段。

正式通知若调整阶段长度、基础伤害/复活等竞赛参数，或规定未知的新网关字段，需要在封存前与当前实现核对；不能把它们偷偷塞进接入JSON当成现场可调算法参数。提前准备官方参数核对表比临场解释全部源码更合适。

当前只需等待官方发布上述接入值。尚未确定的镜像格式、登记/上传入口和重启解释继续作为外部待定事项，不代发消息、不代提交。

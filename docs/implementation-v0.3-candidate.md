## 本轮完成的代码

1. **资源封顶后继续寻找任务资源。** 第二阶段资源分封顶并不表示普通/高资源任务完成。已知资源没有收益时，改用当前地图的未知视野增益选择探索方向；全部可达区域已知且没有收益才WAIT。完成状态仍读官方任务ID，不虚构背包或任务完成数。
2. **逐Tick避险。** 独立EscapePlanner用“Tick偏移＋格子”作状态，允许WAIT等待临时墙失效，不先按静态最近出口剪掉更长路线。每次转移先检查动作Tick的障碍，再检查下一Tick到达位置的预移动危险。搜索最多32Tick/65536状态，缓冲复用；未找到完整路线时返回NoRoute或BudgetExceeded，主流程只做明确标识的局部降损。
3. **临时墙到期的地图校正。** World记录每格障碍首次/最近被看见的Tick。LLM确认分裂窗口结束后，期间新见且结束后未再确认的墙退回Unknown；事件前就看到的静态墙、结束后又看到的墙继续保留。不会直接把模糊格写成Free。未来路径可考虑窗口结束后的通行，当前动作仍按当前Tick校验。
4. **按席位保存已确认增益。** 已验证的granted/ended支持A–D分别存储和结束，不把B/C的增益写到自己身上。敌方无双范围/伤害、个人易伤倍率使用对应事件参数。只采信LLM解释通过的明确授予通知，不凭敌车移动猜测增益；未知增益仍是待完善部分。
5. **结算顺序保护。** 当前Tick的致命预移动爆炸、分裂立即复活强制WAIT，先于攻击收益计算；非致命爆炸先扣可用HP，再估战斗。已确认击杀只移除下一Tick威胁，不取消敌人当前Tick攻击；下一位置风险按剩余HP封顶，避免单步风险无上限地压过死亡代价。
6. **恢复边界。** 即时复活会清空尚未完成的堡垒驻留进度。Tick延后用饱和加法，避免异常大Tick下的有符号溢出。缺少独立事件必要字段时拒绝建档，避免空参数进入危险判断。

这不是完整裁判模拟器。32Tick搜索和固定可见车辆占位是假设边界，不能保证对方未来不争格；没有主动争夺回血/堡垒、高阶追击或集火。范围/伤害参数来自公开公告的LLM结果，不来自官方配置或全图。

## 第三次综合检查发现了什么

测试仍用隔离域39与本地假HTTP服务，真实模型调用0。假服务先挂起事件响应，控制器继续发送Tick0–4：5帧都收到move动作。放行响应后，Tick5按事件避险，Tick6执行任务移动，Tick7防御；控制和正常退出均完成。

最终检查最近HTTP状态时失败：日志显示实际发送了2次，第二次为多余资格请求，最近状态变成500/non_json_body。假服务只实现事件解释响应，额外任务请求走到其不支持的格式分支；没有接触真实网关或DeepSeek。

根因是资格条件只检查“本地是否已见2xx”和“是否排过资格任务”。事件请求仍在途时，这两项都是false，于是又排了一次任务解释。真实服务即便正常回答，也会产生额外开销。不能只删掉测试断言来掩盖它。

## 修复方式及为何仍待复验

增加event_work_pending()，在调度器锁内同时检查排队事件、在途事件、已返回但未消费的事件；控制器还检查自己尚未合并的结果队列。只要有这些事件工作，就不补资格任务。

| 当前状态 | 是否另排资格请求 |
| --- | --- |
| 事件排队/在途 | 否 |
| 结果在调度器队列或主线程待合并队列 | 否 |
| 2xx已合并 | 否，本场已有本地成功观察 |
| 最终失败已消费，且无其他事件工作 | 可以排一次，仍受次数、额度和冷却约束 |

必须连“结果未消费”也检查：HTTP可能在本Tick合并结束后、发布后整理开始前刚好返回，只检查in-flight会漏过这个竞态。状态更新、取消和异常出口均清理在途标记，旧场结果仍按generation隔离。

新增qualification_pending_tests准备检查：请求挂起时pending为true；响应完成但结果未取走时仍true；结果消费后才false。该用例只编译未运行，没有换名字绕过综合场景三次限制。

# 赛前启动与赛后复核操作稿

2026-10-22草稿。供当前自研程序使用，正式接入值按主办方通知填写；不包含密钥。以规则§2、§3及通信协议为准。

## 赛前准备

1. 保存源码包、哈希、虚拟机快照或已核验镜像、启动说明。核对 `source-manifest.json`，固定策略、Prompt和构建选项。
2. 确认本场阶段、席位、队名、ROS域、裁判地址、网关完整地址、模型、输出上限L、配额、本场令牌和网络设置。缺少L时程序禁用AI，第二阶段可能没有任务计分资格；先向裁判确认能否省略 `max_tokens` 或沿用授权默认值，不能擅自猜测。
3. 接指定有线网络。分机使用公告域和 `ROS_LOCALHOST_ONLY=0`；本机练习可用1，不能把本地回环成功当成异机验收。
4. 配置本场席位对应的令牌，仅注入 `RMTC_TEAM_TOKEN`；不用DeepSeek上游密钥替代正式席位令牌。实际接入文件放在源码包外，材料中只附无密钥模板。
5. 确认 `decision_config.json` 只有登记的 `balanced` 或 `collect`；当前程序只启动时读取，不支持赛中热切换。策略切换或重启先走裁判流程，单独登记剩余额度。

启动示例（值需替换成公告值，不要把真实令牌粘贴进笔记）：

```bash
cd /home/ubuntu/projects/RMTC/contestant-v0.1
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=27
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export RMTC_STAGE=2
export RMTC_CONNECTION_CONFIG=/绝对路径/包外接入配置.json
export RMTC_LOG_FILE=/绝对路径/本场日志.jsonl
# RMTC_TEAM_TOKEN 由包外环境安全注入
bash run_contestant.sh A '登记队名' 裁判机IP
```

使用三个位置参数时顺序固定为席位、队名、裁判IP。裁判IP不会自动推导AI地址；包外JSON需含完整网关地址、模型、L等信息。

## 开场前七项核对

| 核对项 | 通过证据 | 异常时处理 |
| --- | --- | --- |
| 进程与版本 | startup记录与预定源码/二进制哈希对应 | 保持暂停，定位版本或启动错误 |
| 本队感知 | 本席位话题有连续有效JSON与正确session | 核查域、网络、席位和类型 |
| 动作提交 | 动作带当前tick/session，阶段内合法 | 保持暂停，查看格式/阶段错误 |
| 实际执行 | 后续self.last_action回填对应动作tick | 区分没发、没收到、未执行、执行失败 |
| AI接入 | 第二阶段本场本席位真实代理成功记录 | 核查401/429/上游故障，不泄露令牌 |
| 日志 | 持续写入、log_dropped=0、磁盘有余量 | 保留原日志，修复目录或容量问题 |
| 操作限制 | 无人工动作/坐标输入，模式已登记 | 取消未授权控制入口或配置修改 |

联调完成后保存必要截图/录屏。只录队伍程序、Tick和回执等证据，不展示令牌或包含密钥的环境/配置。

## 比赛中

监测通信、进程、Tick推进、回执错误、AI本场成功、调用预算及日志丢失。生产程序自主行动，不能人工输入方向、目标坐标或实时战术。

发现进程崩溃、断网或裁判故障，先保存场次与最后Tick，按裁判指令处理。不要反复重启。两次异常重启额度、同ID重置后的重新接入是否计额度、正常重启是否计额度，均需官方确认；不要自行判定豁免。

若获准重启，记录原因、批准人、场次、时间、剩余额度和版本；令牌及正式封存策略不变。当前没有自动拉起守护进程，也未证明崩溃起算两Tick恢复，不能把手工重启承诺成自动恢复功能。

## 赛后五分钟内

保存本场日志、裁判成绩、回执/AI记录和截图，按session分目录。核对资源价值、有效伤害、完成任务、真实调用资格、无效动作与处罚，分数展示简写不替代官方九位小数比较。

离线日志核对：

```bash
python3 -B tools/audit_log.py /绝对路径/本场日志.jsonl --output /绝对路径/本场摘要.json
```

该工具只检查自研日志，不自动证明裁判接收率、官方任务资格或最终计分；需与对应场次裁判记录交叉核对。测试工具读取练习全图只用于验收，不接入生产决策。

复核申请模板：

```text
登记队伍：
场次/session与本场席位：

观察事实（动作、回执、成绩差异）：
对应规则条款：
证据文件/截图及哈希：
希望裁判复核的记录：
```

本稿不向外发送消息或提交材料。语雀报告、镜像格式、录屏与正式登记仍须按主办方通知完成。

## v0.9队伍预检与交付补充

队名肥鱼说的都队，队长蔡礼格，队员李宸梓，分工待确定。已完成常规安装后，先运行bash tools/preflight.sh --seat 本场席位 --referee-ip 本场裁判IP --network wired（本机练习用local），再用bash run_team.sh 本场席位 本场裁判IP启动。正式第二阶段显式设置RMTC_STAGE=2，避免用第一阶段预检掩盖AI配置缺失。

预检只核对本地元数据/配置/安装，不启动ROS、不请求模型、不修改配置。标准入口在本机按域/席位持锁，防止同席位重复运行；不自动重启。检查成功后仍须完成本场网络、动作执行回执和真实AI核验。

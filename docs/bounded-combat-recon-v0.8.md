| v0.6四车mock | 92 | 50 / 0 / 3 | 326 |
| v0.6真实代理、无陪练AI | 105 | 120 / 200 / 3 | 395 |

统计排除终态Tick500，和把终态也计入的历史“reason总数”相差1是预期差异。两场四车的无目标WAIT帧没有可见资源，但分别有75/100帧出现可见车辆；有些已封顶，有些受保护或没有正收益，不能一概归因于“没有敌车”。真实代理场的395帧均没有可见敌车，但有4个可见资源，资源得分已封顶，所以它们不再产生主得分收益。

复盘脚本最初误读`entities`，而实际公开协议是`visible_entities`，资源类型为`resource_normal/resource_high`。核对协议后修正，改成字段缺失直接报错，避免静默当作空视野。首次错误结果保留为`recorded-wait-review-initial-field-assumption.json`，该结果已经废止，引用以修正后的文件为准；没有因此重跑比赛。生产C++感知解析本来就使用正确字段，未受这次复盘脚本错误影响。

四车场结束时伤害已封顶，资源也已被争抢，不能只凭WAIT多就判定策略错误。不过真实代理场从105一直等到499：资源分30、任务分15、伤害分10，总分55；伤害尚有5分空间。原有探索只评价未知地形；当它找不到可达且有正信息收益的未知区域目标时，不会重新观察旧区域，需要等待其他车辆进入视野才会再次发现攻击机会。仅凭P9日志不能断言全部地图格子都已看过。

这份复盘识别了可改进条件，不能证明新策略一定得到60分。旧观测轨迹不能当成新策略执行后的轨迹，新版本没有重跑这场比赛。

## 新功能什么时候执行

新增`recon.hpp/.cpp`，归入P8的信息探索。仅balanced模式且同时满足以下条件时，加入一个视野刷新候选：

1. 当前存活、状态完整、感知实体完整，有可信的1–4格视野半径与有效伤害分数字段。
2. 没有可达的任务/资源得分目标，没有未知地形探索目标，没有已采用的主动事件机会，当前没有可见敌车。
3. 普通伤害得分还未到上限，或还有结构化的未完成effective_damage任务。
4. 已知可走区域有当前视野之外、观察信息较旧的格子；路径可达，既定危险检查通过。

collect和第一阶段不采用该新增候选。死亡、期限避险、任务/资源、未知探索、当前可见战斗继续使用原决策路径。若伤害已封顶且没有未完成的伤害任务，不为这个目的巡查。

## 如何选择观察位置

`World`新增每格最后一次合法观察Tick。完整可信视野刷新对应方格，部分感知只刷新自身及明确报告的实体格；阵亡帧不刷新周边，新地图重置。它只记录观察时间，不保存假定的当前敌方坐标。

候选落点限已知Free、12步以内。估计该位置的视野中，有多少当前看不到、曾观察过的Free格；未知地形留给原探索器，已知墙格不产生找敌收益。两Tick内刚看过的格不计入，信息陈旧程度在20Tick封顶。

候选估值为：

```text
剩余机会 = 尚未获得的普通伤害分 + 未完成且未达目标的结构化伤害任务分
机会估值上限 = min(0.25, 0.05 × 剩余机会)
单位控制Tick估值 = 机会估值上限 × 陈旧Free格权重 / 目标视野格数 / (路径步数 + 1)
```

这是信息探索的折扣估值，不是新的官方分数，也不承诺一定找到或击中敌人。最多保留8个候选检查路线，使用固定数组；对每条路线沿用现有`safe_route`，保留抵达后一次攻击的时间。实际只执行第一步，下一Tick用当前感知重新决策。

候选进入原有攻击/防御/移动的共同受击风险比较，无目标时共同比较跨度仍为1Tick。新模块不发网络请求、不读取磁盘、不解析自然语言公告。已有事件风险继续来自LLM验证结果，实际攻击仍要求当前合法可见目标。

这些数值属于待封存算法常量，不能在现场作为接入参数修改。decision_type仍只有balanced/collect，登记草稿已补充本功能范围。

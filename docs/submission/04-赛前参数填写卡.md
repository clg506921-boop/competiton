# 赛前参数填写卡

正式信息到达后填写仓库外的私有JSON，不通过修改算法更换席位或令牌。模板内的null必须填写，不能直接启动。

## 已由参赛手册明确的内容

| 项目 | 值 |
|---|---|
| 第一阶段 | A席位，stage="1"，100ms/Tick，100Tick，不要求真实AI调用 |
| 第二阶段 | 本场分配席位，stage="2"，500ms/Tick，500Tick |
| 正式模型 | deepseek-flash |
| 正式输出上限 | max_tokens=512 |
| AI请求路径 | POST /v1/chat/completions，具体主机与端口待发放 |
| 资格要求 | 正式第二阶段本场、本席位在结算前至少一次真实统一AI成功调用 |

## 本场需要填写

| 字段 | 来源与注意事项 |
|---|---|
| rules_version | 模板预填v1.2作为当前代码兼容基线；最终版本不同须先核对，不能任意填版本绕过检查 |
| team_name | 已确认：肥鱼说的都队 |
| seat | 第一阶段A；第二阶段按本场实际席位 |
| referee_host | 本场裁判IP，不能填手册中的示例星号地址 |
| ros_domain_id | 所属赛场公开域；双裁判换场时按新值重启程序 |
| network | 默认裁判和正式有线使用wired；local仅用于双方均匹配的回环UDP配置，不能仅因同机就选local |
| gateway_url | 发放的完整/v1/chat/completions地址或程序支持的基址 |
| team_token | 本场、本席位新令牌；不放入报告、截图和Git |
| ai_quota | 发放的本场调用额度；当前代码中0表示本地不限额，不表示禁用AI，不能用0代替未知值 |

模型、输出上限、Tick参数已在模板预填。程序统一构造thinking.disabled及JSON输出请求，LLM并发为1；仍须遵守网关公布的额度、并发与请求大小限制。

## 启动顺序

1. 将对应模板复制到仓库外私有目录，填写本场值并限制文件访问。
2. 在运行ROS的Ubuntu里核对实际有线IP、掩码、路由和ROS域；宿主机与虚拟机不得使用同一个静态IP。
3. 运行prepare_match.sh --check；预检不调用模型，不代表通信或正式AI资格通过。
4. 每个席位只保留一个本队控制器，按裁判安排启动并检查self.last_action。
5. 换场时更新公开域、席位、网关、令牌；session_id/tick从新感知获取，不提前填写。

具体IP、网关/DNS按赛场接入单核对。手册操作示例留空网关/DNS，不把练习地址和域27当成正式分配结果。

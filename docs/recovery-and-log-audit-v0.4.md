# 异常恢复与日志核对（v0.4）

日期：2026-10-22。按已核验的 v1.1.1、v1.1.2 补充稿和比赛规则/协议继续实现。本轮只改自研程序，Ubuntu 中完成编译与验证，Windows 工作目录保留对应源码和交付包。

## 改了什么，为什么

1. **回执不再仅按动作名称判断成功。** 原来发送 move、收到 move，即使带 E_STATE 或 E_SCHEMA，也可能记录 Confirmed。现在先检查错误和执行情况，协议拒绝、移动执行失败、因死亡取消移动分别记录。
2. **失败不等于前方有障碍。** 只有紧接上一动作、仍存活、未复活且仍在原位置的移动执行失败，才短暂避开尝试落点。E_STATE、坏请求、旧回执、未知错误和重生定位不会产生障碍证据。短期避让不会覆盖更长的已有避让期限。
3. **跳帧打断连续证据。** 跳帧、长停顿、复活或非相邻定位后，清空摆动/连续卡住的短期证据和旧目标。保留本场合法地图记忆及按绝对 Tick 管理的事件，不从缺失帧猜测路径或补动作。当前动作始终使用当前 self.position、tick、session_id。
4. **历史回执不能直接证明当前幻术方向。** 仅即时、连续且无错误的成功移动回执用于方向补偿。延迟回执仍可关联历史动作，但不据此改变当前方向。LLM 已验证的效果区间仍由既有事件模块处理。
5. **日志可以分辨进程。** 增加启动记录、run_id、可读回执状态、预期动作、跳帧数、收帧间隔及恢复诊断。错误只输出 E_* 白名单或 UNKNOWN，不回显错误原文。日志线程每行 flush，减少崩溃前已完成记录的用户态缓冲损失；未使用 fsync，不承诺断电后持久化。

回执是在本地“准备并发布动作”记录上关联，不能据此证明裁判实际收到。invalid_actions 仍以裁判分数字段和正式记录为准。

## 回执细分与接口边界

保留原 ReceiptKind 前五个值及编号，末尾增加两个内部诊断值；不改变任何官方输入/输出 JSON。

| 状态 | 含义 |
| --- | --- |
| confirmed | 动作类型相符、无错误；不等于已验证攻击命中或资源入账 |
| rejected | 协议/状态错误或未知错误；即使动作名称相同也不会当成功 |
| mismatched | 动作类型或即时成功移动方向与本地记录不相容 |
| unconfirmed | 当前进程找不到对应发送记录，例如重启后首帧带旧进程回执 |
| terminal_candidate | 保留原定义，本轮未增加自动终局判定 |
| move_failed | MOVE 执行失败，包括 E_BLOCKED/E_OOB；不能直接认定无效动作 |
| state_cancelled | 移动被 E_STATE 取消，且当前明确阵亡或复活；不据此生成障碍 |

方向补偿只依赖结构化执行回执，不解析公告原文、不自行识别事件类型。没有增加人工控制入口、策略热加载或自动申请重启。

## 日志核对工具

新工具 tools/audit_log.py 只读自己的 JSONL 摘要，不访问网络、裁判目录或全图。用标准库实现，限制单行 2 MiB、上下文 128 个和精确 p99 样本 200000 个；超限或损坏会报告摘要不完整。拒绝重复键、坏字段、非有限耗时；报告不回显输入原文。支持旧数字回执日志，但缺少 run_id 的旧日志不能可靠区分重启。

```bash
python3 -B tools/audit_log.py evidence/synthetic-restart-2026-10-22.jsonl --output summary.json
```

输出独立报告；完整且字段一致返回 0，损坏/丢日志等返回 1，文件读写失败返回 2。拒绝把报告覆盖到输入文件。该命令仅复核已有证据，不重新启动测试或比赛。

指标分别统计重复重发、观测 Tick 缺口、回执关联、执行失败和日志损失。receipt_association_rate 是可关联历史动作的回执占比，不是官方动作成功率或比赛验收指标。application_us 仅覆盖程序回调入口至发布，不包括上游 DDS 等待和裁判结算。本工具不替代完整感知回放、得分仿真或裁判记录对账。

通过的场景共两个进程，动作 Tick 为 40、41、44、48、49、50、53、54。首个进程接入 Tick40，在三帧后被测试工具杀死；新进程从 Tick48 和新绝对坐标接入，当帧发出合法 MOVE。Tick49/50 阵亡 WAIT，Tick53 从官方形式的重生坐标恢复 MOVE。原进程三条动作摘要保留；新进程不把旧进程回执错误关联为自己的动作。

审核工具得到 8 条独立动作、2 次启动、4 个故意跳过的观测 Tick、0 条摘要丢失。8 个回执中 4 个可关联，另 4 个刻意设置为迟到接入或缺失 Tick 的回执，因此 50% 关联率符合该夹具，不能当作性能下降或成功率验收。合成回执不代表官方执行。

证据：evidence/recovery-verification-2026-10-22.json，包含编译记录、9 项测试明细、两次进程检查及官方哈希；随包另附成功场景摘要 JSONL。

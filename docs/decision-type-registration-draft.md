# 决策模式与配置登记草稿

本页是供队员理解和赛前登记使用的草稿，尚未提交给主办方，也不表示已经获批。当前源码版本：v0.9（同分收益/启动交付离线验证完成；历史练习证据保留，正式检录尚未完成）；规则/通信协议优先，设计基线为已核验 v1.1.1，参考 v1.1.2。

## 两种预置模式

| decision_type | 共同决策路径 | 攻击准入区别 |
| --- | --- | --- |
| balanced | 阵亡WAIT；已知事件期限避险；比较攻击/防御/移位；任务、资源、主动事件机会、短程追击、探索、WAIT | 攻击统一效用不低于最佳非攻击候选时准入 |
| collect | 与balanced相同的输入、合法性和风险模型 | 额外要求保守场景下可击杀，或已确认普通攻击模型中无反击，并且效用为正 |

这两种模式的“保守场景”均是假设，不宣称知道敌方实时意图或未公开增益。已实现无任务/资源目标时的主动回血、堡垒驻留和最多4步的最近攻击位追击。collect的追击另要求保守场景下可击杀或无反击。机会值是预估，不是官方加分；未知敌方增益、移动对手预测、高阶追击/集火仍未完善，不能把设计中的全部P0–P9当作比赛验收已完成。

配置文件只允许一个键：

```json
{"decision_type":"balanced"}
```

collect同理。程序拒绝额外的动作、目标、坐标、权重等字段。文件只在启动读取，程序不热加载，也不接收人工战术话题、键盘或stdin指令。当前首版不提供赛中切换；两种模式可在赛前选择。暂停/批准/每场最多两次切换的操作与计数模板已准备，程序仍只在启动读取且未做正式切换恢复验收，不能用未获批准的重启绕过限制。

## 决策输入与边界

生产程序只订阅本队感知，使用公开地图尺寸、自身绝对位置、可见实体、结构化任务、执行回执及交给LLM后验证通过的事件解释。世界地图只由合法感知积累；不读取测试端全图、观赛网页、官方配置文件或其他队伍话题。

随机事件原文只做换行分帧、完整正文去重及Prompt封装，没有本地关键词、正则、时间表或句式语义解析。事件窗口使用LLM解释，个人效果区间按本队连续位置/成功回执推导；不足时保持未知。

移动方向补偿使用两类公开依据：LLM确认的幻术窗口，或本队last_action中成功移动的effective_direction与已发送方向的差异。它只补偿MOVE，不反转攻击，不从事件原文直接推断；实际位置始终以self.position为准。这一依据应保留在正式技术报告中。

HTTP只发到按公告注入的统一网关；单worker，最多一条在途，非流式。每来源最多两次实际发送。第二阶段尽早做任务解释或事件解释，但本地2xx状态不替代官方真实调用资格。未接真实服务时不能声称任务得分资格有效。

## 封存与现场接入

正式decision_type仅balanced/collect；研究选项greedy/lookahead/frontier、immediate/mailbox、O2/O3/LTO不是新增正式模式，需在封存前固定，不允许赛中据此改参数。正式模型、L、网关、令牌、席位、域和网络按公告接入，不能将其当作修改算法的入口。

待登记/确认：最终源码与镜像哈希、固定默认模式、两种模式说明、现场允许的接入参数、max_tokens缺省是否获准、同ID重置与重启额度处理。此稿不得冒充官方答复或批准记录。

## v0.8 balanced的信息刷新

balanced在无任务/资源及未知区域目标、无当前可见敌车、无已采用主动事件机会时，若伤害分未封顶或结构化伤害任务未达目标，可重新观察信息陈旧的已知Free区域。只记本队合法观察Tick，当前视野、未知格和墙格不产生这项收益。collect和第一阶段不启用。

固定常量为观察年龄20Tick封顶、至少2Tick、12步路径、最多8个候选路线；估值上限min(0.25,0.05×剩余机会)，再按陈旧视野比例与路径折扣。该估计不是官方积分或敌方位置断言。仍逐Tick重算、沿用事件安全检查和共同受击风险，无目标H保持1。正式decision_type仍只有balanced/collect，这些常量与算法需赛前封存，不能现场手调。本版尚无真实对局增分证据。

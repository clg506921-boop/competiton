# 第 9 篇：C++ 首版实现约束（v1.1.2）

更新：2026-10-21。本篇规定实现接口；比赛语义、策略、时间边界和成绩验收以第8篇为准。本次交付是设计文档，尚未创建或构建参赛程序，也未调用付费模型。旧版评审表已移除，避免与现行要求并存。

## 1. 技术栈和构建边界

C++17、ROS2 Humble、rclcpp、ament_cmake。业务第三方库限nlohmann/json、libcurl、GoogleTest；ROS标准消息和系统线程库按基础设施依赖使用。

| 目标 | 内容 |
| --- | --- |
| bot_core（STATIC） | 协议、状态、规划、策略、安全检查、事件和非ROS支持；不依赖rclcpp/std_msgs |
| turing_bot_node | ROS通信、参数适配、进程入口；链接bot_core |
| replay_tool | JSONL离线输入、假时钟和假传输；默认不联网、不消耗模型额度 |
| test_* | GoogleTest，覆盖真实边界而不是空构造测试 |

目录使用include/rmtc_bot、src、test、tools；core/CMakeLists.txt提供不加载ament的核心构建入口。只创建当前步骤需要的文件，不预先生成空处理器。CMake显式声明C++17和Threads::Threads。Release和Debug+ASan/UBSan使用不同build/install/log目录，记录实际优化选项；Sanitizer覆盖核心编译和最终程序链接，自有代码开启Wall/Wextra/Wpedantic并消除警告。

## 2. 共用数据类型

以下是接口规格，不是已编译代码。坐标是整数Cell，方向和动作是枚举；不能把任意尺寸地图的坐标枚举成固定18×18列表。

```cpp
using Tick = std::int64_t;
using MonoTime = std::chrono::steady_clock::time_point;
struct Cell { int x{}, y{}; };
enum class Dir { Up, Down, Left, Right };
enum class ActionType { Move, Attack, Defend, Wait };
enum class StageMode { Auto, ForceCollect, ForceBattle };
enum class StageEvidence {
  Unconfirmed, CollectConfigured, BattleInferred, BattleConfigured
};
enum class ReceiptKind {
  Confirmed, Rejected, Mismatched, Unconfirmed, TerminalCandidate
};
enum class MoveMapping { Unknown, Normal, Reversed };
enum class GuardOutcome { Publish, SafeWait, NoSend };
enum class ErrorCode {
  Parse, Type, Range, MissingField, WrongSeat, BadRelmap,
  StaleTick, UnknownState, IllegalAction, QueueFull,
  HttpAuth, HttpRate, HttpQuota, HttpUpstream, HttpTimeout,
  BadModelOutput, StaleModelResult
};
struct Error { ErrorCode code; std::string field; };
template<class T> using Result = std::variant<T, Error>;
```

ForceBattle对应BattleConfigured；公开证据确认第二阶段对应BattleInferred。Auto未确认时规划时长100 Tick；确认第二阶段后500。时长只约束规划，不擅自停止接收新Tick或发送合法动作。

| 类型 | 必须保留的字段/含义 |
| --- | --- |
| Observation | session_id、tick、接收steady时间、地图尺寸、vision_radius（optional，缺失不补4）、Self、实体、missions（id/type/target/position）、mission_text、event_text原文、Score、可见格和完整性标记 |
| Self | team、robot_id、位置、HP、alive、protected、defending、respawn_in、position_reason（optional，仅开局/重生首帧）、last_action（optional<Receipt>）；可缺省项用optional，不用0/false代表未知 |
| Receipt | tick、action、moved、effective_direction（optional，仅成功移动）、error（optional，如E_BLOCKED/E_OOB/E_STATE）；回执不含坐标，不用于累加定位 |
| Score | resource_value、effective_damage、mission_completed、mission_completed_ids、invalid_actions，均optional；只作统计与任务去重，不作策略的真值替代 |
| Entity | robot_id、位置、存活、HP、保护、防御等公开字段；无公开依据保持未知 |
| Action | session_id、tick、type、可空dir；WAIT/DEFEND不附方向 |
| Snapshot | 已接受场次、代际generation、世界记忆、目标、Tick计时样本；不保存未完成网络任务 |
| Candidate | 合法动作、共同评估跨度H、期望得分率、本Tick死亡机会损失率、后续位置风险率及依据 |
| Decision | 最终动作、decision_type、原因枚举、引用的结构化证据/事件ID |
| ReceiptRecord | 发送动作、匹配回执、分类、实际位移；TerminalCandidate只代表待核实终局 |

解析先检查类型、范围、坐标和必要字段；JSON解析使用不抛语法异常模式，仍捕获分配等异常。boolean不能作为integer接受。未知可选字段兼容记录，缺核心字段拒收，错误信息不输出令牌。传输错误与业务拒绝使用不同ErrorCode。

## 3. 七个模块及其最小接口

| 模块 | 接口及责任 | 首批边界测试 |
| --- | --- | --- |
| Protocol | parse_observation(text)→Result<Observation>；encode_action(Action)；相对图还原 | 缺字段/错类型、89字符相对图、中心同格 |
| SessionClock | accept(obs,now)→接受/重复/候选/过期；observe_interval(tick,now)；period() | auto时长100、500ms实测、快速新场 |
| World | update(obs,receipt)；snapshot_for_diagnostics；访问/资源/临时阻塞记忆 | 跳帧不造路径、资源消失、旧快照不恢复 |
| PlannerStrategy | decide(context)→Decision；Dijkstra与优先级树 | 终局不可达资源、振荡、攻击/移动共同风险 |
| ActionGuard | validate(decision,current)→GuardOutcome+动作：Publish、SafeWait（时序可信但动作不合格）、NoSend（场次/Tick不可信、旧场旧Tick、已达本Tick提交上限） | 旧场旧Tick必须NoSend、不可用方向降SafeWait、死亡/保护边界 |
| ModelEvents | schedule/normalize/validate/merge；本地个体效果计算 | 代码块/缺null键、185/205/215、入点后效果跨区域截止 |
| RuntimeTelemetry | ROS收发、线程生命周期、有界日志与离线回放适配 | 回调异常、日志队满、Ctrl+C退出 |

SessionClock只收集同场、相邻新Tick的到达间隔，最近最多5个取中位数；重复、跳Tick、跨场及超过5秒的停顿不进入估计。样本不足用已有样本中位数，没有样本用配置初值。全部周期阈值引用period()；前3个间隔尚未齐全时帧间告警采用5秒宽限。估计值和原始间隔都记录，不能把VM变慢解释成程序性能合格。

新场第一帧到来，当前场已至少2个实测周期没有推进，则立即切换并保留一个旧快照；当前仍推进才要求候选两个递增Tick且当前静默达2周期。接受新场次递增generation并清空旧场策略状态，旧LLM结果不能重新生效；旧快照只用于诊断，退休session不自动回滚。同ID低位Tick一律丢弃并告警，不因静默重新接纳；异常重开通过裁判批准的重新接入流程恢复。

策略统一使用第8篇的U(a)。同一组候选共享敌方攻击假设、机会收益基准和H，攻击与普通移动承受相同的本Tick攻击风险，防御单独算减伤。下一位置风险只算后续影响，避免重复扣本Tick死亡。死亡取消移动时，移动采集收益为0；相互击杀仍可有攻击得分。首版模式只有balanced和collect，不保留激进/保守模式的残余枚举或配置。

## 4. 模型输出和本地效果

模型输出先归一化，再使用event-output.schema.json的v3契约验证（schema_version=3）。契约里的required和additionalProperties=false约束归一化后的数据，不直接拒绝带额外字段的原始输出。

处理顺序：限制响应体大小→去首尾空白及单层代码围栏→识别唯一最外层JSON对象→JSON解析→按已知类型和阶段白名单清理未知键→为可空且缺失的字段补null→结构校验→时间/地图/来源/关联语义校验。扫描对象必须识别字符串和转义，不能从第一个左花括号直接截到最后一个右花括号；多个独立对象、冲突重复键和截断对象均拒绝。未知键记录名称，不原样输出其敏感内容。

source_ids/type/phase以及各类型必要参数缺失仍拒绝；缺可空键不代表缺必需业务事实也能通过。每条事件独立校验，可采用同一响应中的有效项；无效项及原因保留，不能因一个坏项丢掉全部正确事件。未知事件只存档。

EventNotice公共字段：source_ids/type/phase；可空announce_tick、at_tick、related_event_id、start_tick、end_tick、trigger_end_tick、effect_end_tick、area、trigger、params、subject_ids。phase为forecast/activated/granted/ended/report。forecast需要生效时间、区域和类型必需参数；activated有related_event_id即可继承，否则字段同forecast；granted/ended必须有related_event_id，granted还必须有subject_ids；at_tick未知保持null，接收帧另存notice_observed_tick，不能替代发生时间；report只存档且params必须null。area为rect/points/square/cross/global，square在本地换算矩形。可推导的end/trigger_end/effect_end由本地按start+params计算，模型值矛盾即拒收。缺关联先缓存待关联，不猜测关闭哪次事件。

请求构造：每次事件请求的user内容包含source_id与原文、当前Tick、地图尺寸、known_events（本场已校验事件的event_id/type/phase/start_tick/end_tick/area，最多16条）以及必要规则摘要。校验时related_event_id必须在本次known_events内，source_ids必须在本次请求内。event_id由本地生成（类型-序号），不让模型命名。

八类型时间映射统一见第8篇，不另建第二套语义。LLM不输出个体effect_start_tick。SelfEffect本地保存授予Tick、combat_from/move_from/heal_from和valid_until，各可空；由事件语义、可信回执和连续状态计算。历史环形缓冲128帧，缺失证据时不追认连续驻留或成功入点。天使入点K回血[K,K+heal_ticks)，heal_ticks来自已校验公告；点消失不截断已得回血。易伤K成功移动，战斗从K+1到该事件共享effect_end_tick前；10和215只用于标准参数或指定示例。公共施放/触发结束与个体效果结束分开，按第8篇类型语义处理。

方向补偿只用成功MOVE对应的发送方向与回执effective_direction核对；只有相邻可信状态、无重生和跳帧时才辅助比较位移，不翻转绝对坐标、不把失败当解除、不臆造50Tick期限。报告和decision_type登记写明结构化回执依据。

## 5. 请求调度、账户和线程

练习使用用户现有DeepSeek账户，费用由用户承担，经裁判测试代理接入；服务和费用归属已确认。接入密钥、代理配置和首次调用尚未执行。正式用官方模型网关和本场令牌。模型名、公告输出上限L的读取方式需在赛前登记，有有效L时max_tokens=L。缺失时只可沿用仍适用于本场的已核验配置，或采用官方明确认可的默认项；其他情况阻止不完整AI请求并告警，主控制继续。L≤0是无效输出限制，不等于配额不限。检录前补齐，避免本场真实调用资格丢失。

冻结超时常量：连接1秒、事件总计10秒、资格/任务总计25秒。现场不能手调这些常量。M0在封存前测真实往返、输出完整性和错误率，再决定是否有证据修改常量；当前不能声称10秒一定足够。

正式最多两路（事件、任务/资格），练习最多一路；每个工作线程复用自己的CURL handle，不能跨线程并用。ROS仅单线程executor，后台HTTP线程不接触ROS状态。任务待办有界8项，单次只含一条新公告，资格待办至多1项；HTTP在途按上述额度控制，不做周期复盘。事件解释成功也可成为本场真实调用成功证据，但HTTP 2xx不替代官方资格确认。

名额状态仅Idle/Busy/Cooling。明确已发送而超时或断连未知结果时，从失败时刻冷却35秒，期间继续占并发名额；明确未发送的失败不冷却。每个来源任务最多两次实际发送，重试先满足冷却与退避，鉴权/配额错误停止，不暗中换账户。旧令牌的冷却不能误记为新令牌已占用，仍要限制进程总线程数。该策略不证明服务端取消，测试报告必须列出冷却导致的解释空窗。

libcurl设置NOSIGNAL=1、连接/总超时、空Expect头、Content-Type、Bearer及明确请求长度；非流式（stream省略或false），请求体≤2MiB，响应上限2MiB，写回调溢出或异常返回失败；不使用Transfer-Encoding分块请求。错误分类按HTTP状态加error.code，错误提示文字不作判断依据（协议§5）：401停本场全部请求；400/404/413/501属请求构造错误，不重试；429 quota_exceeded停本场；429 rate_limit/concurrency_limit冷却后可用剩余1次发送；503 audit_unavailable不重试、提示联系裁判；仅502/504和连接/读取异常按“是否已发送”冷却或重试。非JSON错误正文按状态码分类。日志记录状态码、code、用时、模型标识与安全错误摘要，不记录Authorization或令牌。

事件结果只走mutex保护的有界队列，不使用“最新快照交换”（会覆盖先返回的另一条解释）：队列最多64项，控制线程每Tick最多取16项、预算1ms，按到达顺序合并进EventMemory，过期代际优先清除。生产者不能覆盖队内仍有效的不同事件，队满记录丢弃计数和来源。主循环不等待模型、不发网络请求、不写磁盘。收到新感知先完成时序/定位/回执更新，并在既定预算内合并已经返回且适用于本场的关键事件结果、清理到期效果，然后决策、安全校验、发布；之后做非关键整理。主循环不等待尚未返回的模型。事件预算用尽时记录延迟风险并采取已知风险下的保守动作，不能把已返回的避险结果固定推迟一Tick。

热路径提前分配常用缓冲、复用Publisher、仅处理最新感知，steady_clock计应用耗时。日志有界1024条，由独立线程落盘，满时丢低优先日志并计数；线程不能等磁盘反压主循环。

回调和所有线程入口均捕获std::exception及未知异常；失败记录状态并降级或受控退出，不让异常跨入口。Ctrl+C：停止新任务和动作→通知工作线程取消并用curl进度回调结束请求→join HTTP线程→有界排空日志并join→销毁ROS节点/shutdown。退出路径不能以永久等待网络或日志队列换取完整日志。

## 6. 最小实现顺序与验证证据

1. 类型、错误返回、bot_core/CMake和离线gtest入口，确认真实依赖；只做必要安装或修改，不能把笔记中的依赖当作已安装。
2. 协议解析、相对地图、动作编码与固定样本测试；先证明坏输入不会带出错误动作。
3. 场次切换、实测周期和最新帧处理；覆盖第一阶段最后几步与第二阶段500ms间隔。
4. ROS WAIT闭环，确认场次/Tick/回执一致，再加入采集、恢复、单实例计时。
5. DeepSeek代理接入、归一化、最小事件集合，再做任务和战斗。

第8篇规定20×20与24×24必测图、CPU分配、成绩和次数门槛。本篇不重复另一套参数。四实例测试只验功能；单实例性能需单独测量。参考程序历史三次第一阶段测试不重跑，同场景达到三次失败暂停，不能换编译模式重置计数。

文档附带的JSON仅是契约与输入输出样例。JSON语法检查、Schema验证、C++单元测试、官方裁判联调分别记录；前两者通过不代表后两者完成。下一步是上述第1步，不再扩充首版机制。

核验状态：24个JSON结构样例在包内子集校验器上符合预期（`python3 mini_validator.py`可一键复现，失败返回非零）；Tick区间均为左闭右开[from,until)；归一化、事件内存合并及C++功能尚未执行。新增边界样例见review-regressions.json，均标为待实现验收，不是已通过测试。

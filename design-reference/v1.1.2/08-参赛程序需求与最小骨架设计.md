# 第8篇：首版需求与验收基线

版本：v1.1.2（v1.1.1核验修订＋M0确认项、区间约定、可复现校验），2026-10-21。依据现有规则v1.0、通信协议和官方测试包修正；事件JSON结构沿用schema v3，运行时语义以本版为准。静态核验不替代程序联调及正式赛前公告复核。本篇管理需求、规则和验收；第9篇管理C++接口。当前交付为规格及样例，下一步进入源码骨架；正式赛事代码封存以主办方流程为准。

## 1. 首版范围

先交付第一阶段的通信、采集和异常恢复，再加入第二阶段任务/战斗与必要事件处理。两种决策类型为balanced、collect。优先实现爆炸、世界分裂、辣椒、幻术，以及反伤/易伤安全门；回血和堡垒的主动收益优化后置。

后续版才增加话题历史重建、更多策略类型、同Tick改进动作。同ID低位Tick一律作为过期输入丢弃，不以到达间隔推断重开。若裁判实际重用了ID，应提示裁判确认并按批准流程重新启动，不能自行绕过旧Tick规则。

实现采用C++17、rclcpp、ament_cmake；业务库限nlohmann/json、libcurl、GoogleTest。环境历史基线是Ubuntu22.04.5、Humble、6GiB、8vCPU；参考车18×18图190/200用于对照。

## 2. 启动、阶段与时间

启动接口：`run_contestant.sh <席位> <队名> <裁判IP>`。包为rmtc_bot，程序为turing_bot_node。队名1–96个UTF-8字节且无换行。

| 参数 | 首版规则 |
| --- | --- |
| RMTC_STAGE | 可选auto/1/2，默认auto；缺省仍能启动 |
| RMTC_MAX_TICKS | 可选软时长；auto初始100，确认第二阶段后改500；用户按公告提供的值优先 |
| RMTC_TICK_MS | 周期估计初值；阶段1/auto为100ms，显式2为500ms；随后采用观测值 |
| ROS_DOMAIN_ID、ROS_LOCALHOST_ONLY | 按公告；现有本机域27、回环1；正式异机0 |
| RMTC_AI_PORT、RMTC_AI_URL | 端口默认8000；完整URL可覆盖。练习代理端口8080 |
| RMTC_TEAM_TOKEN | 本场令牌从环境读取；不进入命令行、日志、源码 |
| 模型名、公告输出上限L | 接入元数据；按冻结规则使用，见§7。正式按公告配置；缺失时沿用仍适用于本场的已核验接入配置。只有官方明确认可的默认项可省略，否则阻止该项不完整的AI请求并告警，主控制继续 |

auto初始按第一阶段100Tick计算剩余步数，但这只是规划提示。出现本场合法敌车或LLM确认的第二阶段事件后，锁存第二阶段及默认500Tick。auto未确认只允许move/wait；看不到敌车不会让已确认第二阶段退回第一阶段。公开任务/公告可触发一次模型解释兼资格请求。

`remaining=max(horizon-tick,0)`。在提示范围内优先能按时到达的资源；收到超过提示上界的可信新Tick仍继续行动并撤销过时的剩余时间过滤，不提前停车。终局候选可能被裁判忽略；没有新帧时自然不产生新动作。

### 周期估计

同场相邻新Tick且Tick差为1时，记录steady_clock到达间隔；最近5个合格间隔的中位数作为T。重复帧、跨场帧、跳Tick不入样本。超过5秒的停顿记stall而不进入周期样本；短暂停顿作为异常值保留，由中位数抑制。样本不足5个时用已有样本中位数，无样本才用配置初值。

启动/换场前3个有效间隔为预热阶段，周期告警暂用5秒硬阈值。之后帧中断阈值为max(3T,300ms)，场次静默阈值为2T。所有周期相关判断使用该估计；日志另保留原始间隔、丢帧和与公告周期的偏差，避免自适应把持续VM停顿掩盖掉。墙钟只诊断与调度，绝不推进逻辑Tick。

## 3. 公开通信与状态

全部话题类型为std_msgs/msg/String。

| 话题 | 内容/方向 | QoS |
| --- | --- | --- |
| /team_X/perception | JSON订阅 | RELIABLE、VOLATILE、深度1 |
| /team_X/action | JSON发布 | RELIABLE、VOLATILE、深度1 |
| /team_X/registration | 名称JSON发布，发布者常驻 | RELIABLE、TRANSIENT_LOCAL、深度1 |
| /referee/mission | 任务文本订阅 | RELIABLE、TRANSIENT_LOCAL、深度1 |
| /referee/event_text | 事件文本订阅，首版不用于恢复策略 | RELIABLE、TRANSIENT_LOCAL、深度128 |
| /referee/team_registry | 名称JSON，可选订阅 | RELIABLE、TRANSIENT_LOCAL、深度1 |

策略只使用本席位公开数据和合法记忆。评估者可查看裁判全图/配置/日志，但这些信息不反馈给策略。事件原文由官方网关LLM理解；模型输出可本地做JSON清洗、类型/范围/关系校验。

关键感知：tick是非负整数，拒绝bool/float；session_id为字符串；self.team匹配席位；位置/地图尺寸合法。关键时序或定位错误丢帧；状态不足但时序可信时WAIT。可选统计/回执用optional，不编造0或false。实体损坏或超视野时丢弃该条并标观察不完整，不据此删除资源或清空地图。

坐标左上为原点，x向右、y向下：up=(0,-1)、down=(0,1)、left=(-1,0)、right=(1,0)。实体相对图9行×9列、8个换行，共89字符；中心(4,4)是1，唯一2在(row,col)时位移=(col-4,row-4)，合法无2图表示同格。协议样例结果为[1,-2]。自身位置每帧采用self.position，回执不用于累加定位。

动作统一编码小写，move/attack带方向，wait/defend省略方向，≤4096字节。第一阶段只move/wait；阵亡只wait；保护期不attack。新Tick一次候选；重复可信帧重发同一缓存且不推进策略，每Tick累计最多8次，超量告警。

### 场次选择

| 条件 | 首版处理 |
| --- | --- |
| 首帧 | 直接建立场次，可从非0Tick开始 |
| 当前场新Tick/重复/旧Tick | 分别推进、缓存重发、丢弃 |
| 不同场首帧且当前场≥2T未推进 | 立即切换并处理这一帧；保留一份旧状态快照 |
| 不同场到来而当前场仍活跃 | 暂存候选；候选至少2个不同递增Tick且当前场自候选出现后停止推进≥2T，再切换 |
| 两场都推进 | 优先当前场，告警多源冲突，不逐帧来回清图 |
| 已退休场次重新来帧 | 作为迟到或多源冲突丢弃并告警，不恢复旧规划；旧快照只用于诊断 |
| 同ID旧Tick/明显回退 | 丢弃，不降低当前Tick；重复低位序列提示异常。确认重开需裁判通知及批准的重新接入流程 |

接受新session_id后提升generation，清空旧场规划、动作、事件、效果和地图状态，重置周期估计；旧异步结果失效。保留的一份旧快照仅用于诊断，不恢复为策略输入。静默阈值不能证明消息来源正确；上线须验证唯一裁判源，正式多源冲突时告警，不自动回滚到已退休场次。

## 4. 第一阶段策略

完整可信视野内未报告障碍的格子记Free；阵亡空实体不刷新。已知障碍不可走，Free代价1，Unknown代价1.2，使用Dijkstra距离场，一次搜索评价多个目标；每Tick验证第一步。视野0时允许地图内单步试探。

优先资源：`value/(path_steps+1)`，按当前软时长过滤明显来不及的目标。资源自动采集，无collect动作。失效/不可达目标立即重选。

无资源路线时探索：`new_visible_cells/(path_steps+1)-0.25*recent_visits`。当前前沿有效时，新分数必须超过`旧分+0.2*max(abs(旧分),0.1)`才切换；资源出现、危险、目标失效和停滞可打断。连续4个有移动意图的Tick无位移，或A-B往返3轮，触发重规划。第一阶段完整观察后E_BLOCKED是地图一致性告警，临时封边2Tick并重看，不能无限撞。

蛇形覆盖只作为可选基线；收益比较使用官方裁判并计入场景三次预算。离线回放评估解析、局部规划与耗时，不模拟改变动作后的整场收益。

## 5. 第二阶段：统一风险再按优先级选动作

规则是**攻击先结算、存活车辆再移动**；双方普通攻击同时扣血，击杀对手不能撤销其同Tick已参与的攻击。攻击与移动面对相同的当前普通攻击暴露；defend按规则减伤，攻击还可能有反伤，移动则影响之后的位置风险。

所有合法候选——attack、move、defend、wait——使用同一收益模型：

`U(a)=预期得分率(a)-当前死亡机会损失率(a)-下一位置风险成本率(a)`。

同一决策共用比较跨度H：最佳可达资源/任务距离，截到1–5Tick；没有目标取1。收益和损失先在相同H内估算为分数，再统一除H。对所有候选用同一敌方攻击场景集合与损失基准，HP/事件不明时记录区间，不能只给attack扣死亡成本。move若当前战斗会死亡，不得计入随后采集收益；attack的同Tick有效伤害即使互相击毁仍可计入。defend不减免爆炸/辣椒等环境伤害。

死亡损失估计包含死亡当Tick失去的后续动作、随后3次复活等待及位置重置机会；复活保护允许移动，不当作2Tick停摆。各动作使用相同的替代收益基准，不能把相同当前受击风险算成仅攻击的劣势。至少测试“攻击/移动当前受击相同”“防御可避免致死”“移动死亡无法采集”“反伤只影响攻击”四种局面。

普通20有效伤害最多1分，普通资源10最多2.5分，任务5分；分别在D=300、R=120处截断。有效伤害按目标剩余HP及多人分摊估计，不算过量伤害。资源/伤害封顶后，同分优势作为次级收益。

| 优先级 | 候选准入 |
| --- | --- |
| P0 | 阵亡WAIT |
| P1 | 事件期限内可行的避险/降损 |
| P2 | 合法攻击，按模式门槛比较统一U；不把上帧defending当当前意图 |
| P3 | 被威胁时比较defend、move及wait的统一U |
| P4 | 未完成且可达任务，按5分与时间排序，尽早完成顺路/临期任务 |
| P5 | 仍有得分/任务收益的资源 |
| P6 | 已实现的事件机会，首版不主动争夺回血/堡垒 |
| P7 | 有正净收益的追击 |
| P8/P9 | 探索/WAIT |

balanced：P2的U不低于最佳非攻击候选才准入；collect：还须有可靠击杀收益或目标无法在已确认攻击模型下还手，且U>0。两者顺序相同，准入不同。保护期默认去可达目标；无收益且原地保护有用时WAIT。

## 6. 模型输入、输出与时间语义

首版仅感知event_text，按session_id+单条完整正文去重，每请求1条新公告。模型解释单场公开文本，返回source_ids对应结果；不能本地按关键词解析原文。事件结果只走有界队列，由控制线程合并，旧generation结果丢弃。

**每次事件请求附带known_events**：当前场次已校验事件的event_id、type、phase、start_tick、end_tick和area，供模型给granted/ended/report/无Tick的activated公告填related_event_id；related_event_id必须属于本次请求列出的集合，否则拒收。上限16条，按未结束且最近的优先，超出时附摘要计数。

### 宽容输入，规范内部结构

处理顺序：移除外围空白/单层代码块 → 用识别字符串转义的括号扫描提取唯一顶层JSON对象 → JSON解析 → 忽略未知键并记录字段路径 → 缺少可空键补null → 按类型/阶段校验。多个顶层对象、重复冲突键、核心字段缺失、类型错误、越界或矛盾时间仍拒绝；有效条目可独立采用。字符串“75”不自动变整数，缺damage不猜80。

[event-output.schema.json](event-output.schema.json)描述**归一化后的schema_version=3结构**，不要求模型原始文本逐字满足它。源例、可恢复包裹及拒绝例见[event-output.examples.json](event-output.examples.json)：协议原文1条、练习模板填充样例覆盖全部8类及生效/授予/刷新/解除/结束/命中通知、10个负例、6个归一化用例和6个本地效果用例，24个结构样例已用包内子集校验器复核符合预期；6个归一化及6个本地效果样例尚是预期数据，不宣称功能测试通过。完整JSON Schema标准验证及运行时语义测试待完成。模板样例只用于Prompt示例和gtest，策略运行时不读stage2.json，也不按模板句式解析公告。unknown事件仅记录。

公共字段为source_ids、type、phase；其余可空字段在归一化后出现：announce_tick、at_tick、related_event_id、start_tick、end_tick、trigger_end_tick、effect_end_tick、area、trigger、params、subject_ids。area以kind区分rect/points/square/cross/global：天使与辣椒的公告可含多个点位，用points数组；堡垒公告给“中心+边长”，用square由本地换算矩形，避免模型做坐标算术。params仅记录公告公共参数，持续时长统一记为duration_ticks；可由start_tick+params推导的end/trigger_end/effect_end可为null，由本地推导，模型给出的值与推导矛盾即拒收。删除模型输出中的个体effect_start_tick语义。

| phase | 事件字段解释/必须信息 |
| --- | --- |
| forecast | start是预告的未来激活Tick；必须有start、area、trigger和该类型必要params；announce可空 |
| activated | 生效公告常不含Tick（如“幻术生效……”）：有related_event_id时其余字段可null并继承预告；没有关联时必须带齐forecast字段 |
| granted | 获得/刷新通知；必须有related_event_id及subject_ids；公告写明到期Tick（如“Tick 67 解除”）时填effect_end_tick。at可null，未知发生时间保持null；接收帧Tick另记notice_observed_tick，仅作观测时间，不能填进at/start或据此计算持续期 |
| ended | 解除/结束通知，必须有related_event_id；subject_ids=null表示结束公共施放或触发窗口，是否联动已获效果按该事件规则确定；非null只针对指定对象效果。公告多不含Tick，at未知保持null，接收Tick另存 |
| report | 命中/触发/重生等通报（如“B 号战车受到爆炸，实际损失35 HP”）；params必须null，只存档，不激活、不改效果；HP始终以感知为准 |

授予/结束只作为已关联事件的更新，area/params可null并继承；无法唯一关联先存为待关联通知，不批量结束同类型全部事件。时刻未知时优先采用明确的绝对截止和可信回执：如last_action.tick=K证明成功入点，则按K计算；不能拿初次收到历史公告的Tick当作K。未知时间的旧解除公告不得覆盖已证实的更晚刷新。

公共窗口与个体效果分开存储：幻术施放结束不解除命中者的反转；天使点消失不解除已有回血；天下无双堡垒结束会结束对应无双效果；易伤触发窗口结束不提前结束共享截止前的易伤。已结束公共窗口、仍有个体效果的事件必须继续可关联，known_events优先包含这些记录。公告中的robot_id是席位字母，与感知self.robot_id/实体robot_id对照，只有subject_ids含本席位才更新自车效果。

### 八类型时间字段（forecast/activated）

区间约定：本篇及examples/review-regressions中所有Tick区间一律左闭右开[from,until)，until为首个不再生效的Tick；如回血[117,127)共10Tick。

| 类型 | start/end/trigger_end/effect_end | 本地个体效果 |
| --- | --- | --- |
| explosion | start=T；其余可null | T移动前一次爆炸，无个体持续期 |
| illusion | start=T，params.effect_ticks；本地effect_end=T+effect_ticks | 结合状态T的位置/存活判断，自车MOVE受影响到共享截止；granted给出的个体到期Tick优先；ATTACK不反转 |
| angel | start=T，area=points，params.duration_ticks/entry_window_ticks/heal_ticks；本地end=T+duration，trigger_end=T+entry_window | 自车成功入点动作K：回血期[K,K+heal_ticks)，战斗后当Tick开始；刷新重新从K计 |
| unrivaled | start=T，area=square(center,size)，params.duration_ticks/required_dwell_ticks/attack_size；本地end=T+duration，攻击半径=(attack_size−1)/2 | 本地连续驻留达标于K，攻击增益从K+1可用于战斗，统一到end |
| world_split | start=T，area=cross，params.duration_ticks；本地end=T+duration | T线上强制复活/WAIT，墙到end消失 |
| chili | start=T，area=points，params.duration_ticks；本地end=trigger_end=T+duration | 成功入点K只在K移动后触发火线 |
| reflection | start=T，params.duration_ticks；本地end=T+duration | [start,end)攻击防御目标时评估反伤 |
| vulnerability | start=T，params.movement_window_ticks；effect_end优先取公告明示的统一截止，否则T+params.vulnerability_ticks，二者都缺则拒收 | 自车触发K（K<T+movement_window）后，战斗影响[K+1,effect_end)，不按K重新计总时长 |

规则§8.9固定样例：start=185、trigger_end=205、end=215、effect_end=215。若自车动作190成功移动，战斗易伤从191至215前；若204触发，则从205生效，205触发窗口已关闭。

模型负责理解公共事件，个体效果由本地可信回执、位置历史和授予通知计算。漏帧无法确认连续驻留时不补算达标；自己的实际HP始终来自感知，不由效果预测覆盖。

成功MOVE回执与实际发送方向相反时记录Reversed并补偿后续MOVE；相同则Normal。失败不解除反向观测；模型可提供期限。技术报告与策略登记说明：这是结构化执行反馈，不是事件文本解析，不推定固定50Tick，也不再次翻转self.position。

## 7. 模型服务、预算与封存

练习服务已确定：用户现有DeepSeek账户，用户承担费用，通过裁判练习代理接入。密钥在后续安全接入步骤配置；正式仍仅用主办方网关及本场令牌。

冻结代码规则：事件HTTP总超时10秒、资格25秒、连接1秒；这些常量现场不手调。max_tokens直接采用公告输出上限L，模型名和L属于按公告提供的接入元数据，赛前登记读取方式。正式请求按公告填写model和max_tokens；协议允许默认model不代表允许忽略公告输出限制。配置缺失时先沿用仍适用于本场的已核验值；只有官方明确认可默认值或省略方式时才启用相应回退。其他情况阻止不完整的AI请求并告警，主控制继续执行，检录前必须补齐。L≤0视为无效接入配置，不能套用“配额0代表不限”含义。资格请求在接入配置核验后尽早发送，避免到终局才发现缺失。练习L记录在代理接入配置。首版每组1条，短Prompt只要求必要字段，实际输出不会因上限较大而必须填满；M0测长度/往返以验证完整性，若需改常量，必须在正式封存前做。

正式最多2路请求，其中1路留给事件，后台做一次任务解释兼资格；练习代理最多1路。首版无周期复盘，每来源任务最多初始+1次额外发送。任一属于本场的真实成功可贡献资格记录，不另发无意义资格请求。

| HTTP/code（协议§5） | 首版处理 |
| --- | --- |
| 401 missing_token/invalid_token | 停止本场全部请求，告警令牌问题 |
| 400、404、413、501 | 不重试，记录错误并本场降级；封存期间不得现场改代码，修复只能在允许窗口完成 |
| 429 quota_exceeded | 本场停止调用 |
| 429 rate_limit/concurrency_limit | 冷却后可用剩余1次额外发送 |
| 503 audit_unavailable | 不重试，保持本地决策并提示联系裁判复核 |
| 502、504、连接/读取异常 | 按“是否已发送”进入冷却或立即可重试，受最多2次发送约束 |
| 2xx但内容不合格 | 已消耗额度、可能已计资格；不为内容重发同一公告，记录拒收原因 |

首版简化名额：已提交请求超时/断连且结果不明，该名额冷却35秒，冷却从超时/断连发生时开始；明确未发送的连接失败不冷却。它是保守运行规则，不能当作网关真实释放确认。事件单次最坏约10+35=45秒；资格约25+35=60秒；再发一次的上界约91/122秒（分别含1/2秒退避），遇场次结束/无用则取消重试。已占用和冷却均算入并发额度，旧令牌状态与新令牌隔离。报告明确记录降级时间。

A→模型返回→首次相关动作的耗时是观测指标，不能由1秒目标强制截断请求。爆炸在T移动前触发，模型返回时状态N、需d步，必要条件N+d≤T；晚到解释可以服务持续效果，不能补躲已经发生的爆炸。报告全部危险事件的及时、迟到、失败数及实际避险率。

## 8. 验收场景与资源分配

已核对原始stage1/stage2配置均18×18、16资源、总值200。评估复制配置到隔离测试目录，经官方validate_config检查，再由官方裁判运行；策略不读配置。任务坐标只读missions，测试中的[12,12]不写入策略。

| 场景 | 目标/用途 |
| --- | --- |
| S1基线18×18 | 资源120→160，10/25冻结线180/200，冲刺190/200 |
| S1标准20×20 | 必测；16资源、总200、100动作；交付线160，优化目标180；不能用18×18成绩替代 |
| S1变体 | 第二个预登记变体，改变起点/障碍分布，资源目标160 |
| S2标准24×24四车 | 必测；自己A对参考BCD、自己四实例各为登记场景；任务点从公开感知获取 |
| 离线≥1000条多样样本 | 解析、局部规划、归一化和应用耗时；不推算整场改策略后的成绩 |

固定CPU方案供后续测试：单实例性能测量用裁判0–1、自己2、3留诊断；四实例功能测量用裁判0–1，A/B/C/D分别2/3/4/5，6–7留系统。四车方案扩展了历史CPU0–3运行范围，首次测试前用`nproc`和`lscpu`确认在线核≥8；不足8核时按实际在线且本进程允许使用的CPU集合制定分配，不能假定CPU1–3存在或可用；有资源余量才启动四实例，只验功能。启动前另核对内存余量、亲和性和soft lockup；不修改VM配置。四车只判断功能/恢复，延迟及错窗作为负载诊断，不能推断单实例性能。若过载或裁判停顿导致场景失效，保留证据并计入次数，不给策略算有效成绩。

通信指标：协议类拒绝0、invalid_actions=0；发布与回执分Confirmed/Rejected/Mismatched/Unconfirmed/TerminalCandidate。move→wait需诊断，可能是死亡取消或拒绝，不一律判错窗。TerminalCandidate只标潜在终局提交，离线确认真实结束后才从有效动作窗口中排除；若后续收到执行回执仍转Confirmed。

单实例应用延迟目标p99≤5ms、验收上限30ms；报告样本量、max、帧间隔和DDS匹配。重启从进程创建到首个确认回执目标≤3秒，分段记录启动/发现/首帧/发布/回执。模型解释、策略和运行性能分别留证。

异常必测：重复/旧/跳Tick、快速新场及活跃多源、软时长越界、暂停恢复、坏输入、资源失效/振荡、复活保护、反向回执、慢模型/未知字段/缺可空键、缺L/模型名的已核验配置回退或拦截、无Tick生效公告经known_events关联、501/503不重试、同ID旧Tick丢弃、线程异常和日志队满。同场景最多3次，第三次失败自主暂停；版本或编译模式不重置次数。

### 正式封存、策略切换与接入验收

decision_config.json只能含已登记的decision_type枚举，本版为balanced/collect。每队每场最多两次人工切换，必须暂停期间或加赛前申请，裁判批准登记后修改，恢复时生效；不允许夹带坐标、目标、Prompt或其他参数。程序不因任意文件变化就立即切换，正式操作流程必须与裁判批准记录对应。

异常人工重启每阶段原则上最多两次，不暂停、不补时，使用封存版本。第一阶段后的统一调整窗口按规则允许修改参数、Prompt及任务解析，其他轮次没有自动修改窗口。接入参数变更不得变成策略调参。

正式检录按通知明确阶段、软时长、周期、席位/新令牌、ROS域及网关信息。auto是容错模式：见到敌车或LLM确认事件能提供第二阶段证据，但不能保证第二阶段开局立即出现这些证据；500ms实测周期也不单独作为阶段真值。正式第二阶段优先按已公布阶段配置启动并检查本场真实调用。全网共享每来源IP的100 POST/10秒限额，四实例总请求须纳入测试；并发上限不是频率限额的替代品。
